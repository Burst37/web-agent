Smooth scroll

Native first. Lenis only with a reason.

A smoothing library replaces the browser's scrolling with your own. That is a real cost: it can break find-in-page position, scrollbar dragging, accessibility tooling and every other ScrollTrigger on the page if it is not wired into the same tick. Ship it when the design genuinely depends on continuous scroll easing — not by default.

01

One clock. Lenis must run inside GSAP's ticker, not its own rAF loop, or the smoothed position and the scrubbed timelines drift a frame apart and everything feels loose.

02

gsap.ticker.lagSmoothing(0). GSAP's lag smoothing fakes elapsed time after a long frame; combined with an easing scroller that produces visible jumps.

03

Never hide the scrollbar and never intercept the wheel to move to a fixed destination. Smoothing eases the position the user asked for; scroll-jacking replaces it.

04

Reduced motion turns it off completely — the page falls back to the browser's own scrolling, which is the correct behaviour, not a degraded one.
